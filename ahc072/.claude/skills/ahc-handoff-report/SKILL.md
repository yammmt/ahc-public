# AHC 引き継ぎ・報告の簡潔化

AHC プロジェクトで、次の AI または人間が作業を再開するための指示書・報告書を作成または更新するときに使う。
目的は、必要な判断材料を残しつつ、次の担当者が読むコンテキストを最小限にすることである。

## 読む範囲

- まず現在の依頼、`AGENTS.md`、対象の現行指示書または現行報告書だけを読む。
- `_ai_inst/_archive` と `_ai_out/_archive` は、ユーザーが明示的に許可した場合だけ読む。
- 生ログ、全ケース出力、大きな JSON は読まない。必要な値は、既存の要約・集計から取得し、足りないときだけファイル、キー、行範囲を限定して読む。
- 過去資料を読む必要があるときは、次の作業の判断を変える一点だけを抽出する。経緯の再掲はしない。

## 指示書

本文は原則として 1,200 日本語文字以内を目安にする。実装の自由度を不必要に狭めず、次だけを記す。

1. 目的と変更対象
2. 保持する不変条件・明示的に変更しない範囲
3. 受け入れ条件と、実行前に準備する検証
4. 実行する評価の範囲と、結果後に停止する AHC ルール
5. 現行状態を再現するために必要なファイルを最大 3 件

座標列、詳細な手順、全ログの数値、既知の背景説明は、実装判断や受け入れ判定に不可欠な場合にだけ含める。参照先は「なぜ読むか」を一言添え、アーカイブを参照先にしない。

## 報告書

本文は原則として 1,500 日本語文字以内を目安にする。先頭に次の順で書く。

1. 結果 — 実施内容、比較基準、主要な数値、合法性・エラーの有無
2. 変更 — 変更ファイルと、解法上の意味を最大 3 点
3. 次回の開始点 — 現在の HEAD、未解決の問い、読むべき現行資料を最大 3 件
4. 証拠の所在 — 詳細ログ・JSON・固定入力などのパス

表は比較に必要な行だけにする。全ケースの列挙、内部カウンタの分布、実装の逐語説明、同じ結論を支える複数の数値は詳細証拠へ移す。結果から新たな解法変更を行ったように読める表現を避け、実行後は AHC ルールに従って停止状態を明記する。

## 詳細証拠とアーカイブ

- 再現に必要なログ、JSON、差分、固定入力は対応する `_ai_out/<task>/` に保存し、本文にはパスだけを置く。
- 現行作業に不要になった指示書・報告書は `_ai_inst/_archive/` または `_ai_out/_archive/` へ移し、現行資料から参照を外す。
- 次回必ず必要になる結論だけは、アーカイブではなく短い現行資料に反映する。

## 完成前の確認

- 次の担当者は、本文と最大 3 件の参照だけで開始できるか。
- 数値は比較元、ケース数、単位を伴い、結論と矛盾しないか。
- 詳細情報を必要以上に本文へ複写していないか。
- 指示書・報告書とも、解法プログラム実行後の停止規則と矛盾しないか。
